# 허브 카탈로그와 출처 표시

출시용 카탈로그 `hubs.json`은 의도적으로 비어 있다. **행정구역과 보행 접근성 검토를 완료한 만남 지점이 아직 없다.** 운영 환경에서 미리보기 데이터로 몰래 대체하지 않는다.

두 공개 출처는 서울특별시의 [역사마스터 정보](https://data.seoul.go.kr/dataList/OA-21232/S/1/datasetView.do)와 [버스정류소 위치정보](https://data.seoul.go.kr/dataList/OA-15067/S/1/datasetView.do)다. 둘 다 **공공누리 제1유형 / KOGL Type 1**으로 표시되어 출처를 명시하면 재사용·변경할 수 있다. 파생 데이터를 표시하거나 배포할 때 다음 출처 표기를 유지한다. **서울특별시 서울열린데이터광장, 서울시 역사마스터 정보·서울시 버스정류소 위치정보; 후보 추출 및 정규화**. 정확한 수집 형식, 출처 날짜, 원본 파일명, SHA-256은 `sources.json`에 기록되어 있다. 원본은 `raw/`에 보관한다. 버스 JSON은 재현 가능한 추출 결과이며 별도 공급자의 데이터가 아니다.

| 자료 | 개수 | 의미 |
| --- | ---: | --- |
| 철도 원본 레코드 | 784 | 출처의 역·노선 레코드 수. 중복 없는 검증 완료 만남 지점 수가 아님 |
| 버스 원본 레코드 | 11,236 | 일반·마을버스 정류장과 선착장 포함 |
| `hubs.preview.json` | 589 | 철도 528개, 버스 61개. 행정구역 대조 완료, **대표점·보행 접근성 미검토** |
| `hubs.sample.json` | 100 | 지역 밖 제외 후 재선정한 철도 50개·버스 50개. **대표점·보행 접근성 미검토** |
| `hubs.json` | 0 | 출시 적격성 확보가 차단된 상태 |

`regionCode: "unreviewed"`는 서울이 아니라 미확인을 뜻한다. 현재 생성물의 11·28·41은 좌표 법정동 대조 결과이며 대표점·보행 접근성 승인이 아니다. 서울 데이터셋에는 시 경계를 벗어난 수도권 교통망 레코드도 있다. 북위 36.8–38.3°, 동경 124.5–127.9°의 넓은 범위는 오류를 거르는 기준이며 **행정구역 경계가 아니다**. 이 범위만으로 서울·경기·인천 소속을 증명할 수 없다.

## 2026-10-28 검수 진행

600개 후보의 원본 무결성·재현성 및 좌표 법정동 조회를 완료했다. 서비스 지역 안 589개, 밖 11개이며 100개 표본에는 충남 봉명역이 포함된다. 이는 부분 검수로, 대표점·보행 접근성까지 완료한 거점은 0개다. 해당 600개와 과거 100개 입력은 Git 커밋 `44a9330` 및 조회 근거 파일로 보존했다. 현재 생성 과정은 조회 근거를 대조해 지역 밖 11개를 제외한 589개와 새 100개 표본을 만든다. [검수 결과와 다음 작업](../docs/HUB-REVIEW.md), [전체 좌표 대조 근거](review-evidence/preview-2026-10-28.json)를 참고한다.

## 재생성과 검토

1. Node 24를 사용한다. `python scripts/extract-hub-sources.py`는 Python 표준 라이브러리로 포함된 버스 XLSX를 결정적으로 추출한다. Excel 설치는 필요 없다.
2. `npm run catalog:preview`는 [법정동 조회 근거](review-evidence/preview-2026-10-28.json)를 현재 지점의 fingerprint와 대조하고 서울·경기·인천 밖을 제외한 미리보기, 표본, `quality-report.json`을 생성한다. `hubs.json`은 쓰지 않는다. 근거 누락·중복·좌표/이름/출처 날짜 변경·잘못된 응답·기존 승인과의 모순은 생성을 중단한다. 새 스냅샷에는 맞는 조회 근거를 다시 연결해야 한다.
3. 채택할 대표 지점마다 공신력 있는 행정구역 경계, 역·정류장 도면, 안전한 공공 보행 접근성을 대조한다. 안정적인 허브 ID를 키로 하여 실제 증빙을 `data/reviews.json`에 추가한다. 증빙은 주장하는 점검 사항을 뒷받침해야 하며, 불리언 값만 설정하는 것은 검토가 아니다.
4. `npm run catalog:build`는 모든 후보가 검토와 구조 검증을 통과할 때만 출시용 카탈로그를 쓴다. 현재 실패는 의도된 동작이다. 빌드 실패 시 이전 출시 결과물은 그대로 유지한다.

검토 구조 예시이며 **증빙이 아니다**.

```json
{
  "seoul-rail-SOURCE_ID": {
    "regionCode": "11",
    "reviewer": "actual reviewer",
    "reviewedAt": "2026-10-05",
    "evidence": ["https://official.example/actual-point-review"],
    "pedestrianAccessChecked": true,
    "representativePointChecked": true,
    "fingerprint": "SHA-256 from reviewFingerprint(hub)"
  }
}
```

검토 완료로 허용되는 행정구역 코드는 11(서울), 28(인천), 41(경기)이다. `reviewFingerprint`는 `scripts/build-hubs.mjs`에서 내보내며, 출처 ID·정규화한 이름·좌표·출처 날짜에 검토를 연결한다. 지점이 바뀌면 이전 승인은 무효다. 비어 있는 `reviews.json`이 현재의 실제 상태다.

## 선정 기준과 품질 한계

- 안정적인 ID는 `seoul-rail-{BLDN_ID}`, `seoul-bus-{NODE_ID}`이며 이름이나 배열 순서에 의존하지 않는다. 좌표는 원본 숫자 값을 유지하며 임의 지오코딩이나 중심점을 만들지 않는다.
- 버스 후보는 원본의 `중앙차로` 분류를 간선버스의 재현 가능한 대리 기준으로 사용한다. **노선 연결 수에 따른 순위도, 좋은 만남 지점이라는 증거도 아니다.** 다른 버스와 선착장 8개는 제외하므로 이 기준 밖의 주요 버스 허브가 누락될 수 있다.
- 같은 교통수단 내 정규화된 이름의 중복과 동일 좌표는 자동 병합하지 않고 **격리**한다. 대표 지점 선별 전까지 유용한 환승역과 반대 방향 정류장도 상당수 의도적으로 제외된다. 이름만으로 환승 연결이나 공통 보행 만남 지점을 증명할 수 없다.
- 원본 6행은 넓은 좌표 범위를 벗어나거나 좌표가 유효하지 않다. 10,831행은 버스 후보 분류 밖이고, 583행은 이름·좌표가 중복된다. `quality-report.json`에 출처 ID와 사유별 제외 목록이 있다.
- 100개 표본은 각 교통수단 안에서 위도·경도로 정렬한 항목을 균등하게 뽑는다. 재현 가능한 테스트 집합이며, 이동 수요를 통계적으로 대표하는 표본이나 사람이 검증한 인수 테스트 집합은 아니다.
- 현재 후보 589개(지역 밖 제외 전 600개)는 목표인 1,000–3,000개보다 적다. 수도권 전체를 포괄하지 못하며 인천·경기 버스 출처, 노선 연결성, 공신력 있는 행정구역 분류, 환승 대표 지점 선별, 보행 접근성은 미완료다. 숫자 목표를 맞추기 위해 이 절차를 우회하지 않는다.
- 요청에 따라 KRIC의 2026-06-30 전국 자료를 조사했다. 해당 페이지에는 파일별 재사용 조건이 명확하지 않았고, 포털 일반 약관에는 제한이 있었다. 배포 가능한 결과물에 포함하지 않았으며 추가 전에 적용 라이선스를 확인해야 한다.

매월 날짜가 명시된 새 스냅샷을 내려받아 라이선스·출처·해시를 기록하고, 필요하면 필드 추출을 조정한 뒤 검토를 반복한다. 출처 날짜를 덮어쓰거나 좌표가 바뀐 지점의 승인을 유지하지 않는다. `generatedAt`은 저장소에 등록된 스냅샷 묶음 날짜로 고정하고 버전은 콘텐츠 해시로 정하므로, 입력이 같으면 재생성 결과도 바이트 단위로 동일하다.

## 보행 근거 원문 대조 — 2026-10-28

[철도 표본 대조 JSON](review-evidence/rail-access-2026-10-28.json)은 현재 철도 표본50개에 대해 설치행18역·좌표 노드19역·안내도17역의 대응 후보를 기록한다. 안내도17장은 직접 읽었지만 원본 거점의 정확한 공공 만남 지점·현재 접근성 승인과는 구분한다. 출처별 다운로드 주소/양식·기준일·해시와 지점별 미해결 사항은 JSON 및 [검수 보고](../docs/HUB-REVIEW.md)에 있다.

- 서울교통공사 엘리베이터 설치현황868행은 [원본 CSV](raw/seoulmetro-elevators-20260901.csv)를 CP949 그대로 보존했다. 공공데이터포털 원문은 이용허락범위 제한 없음으로 표시한다.
- 서울특별시 엘리베이터 좌표는 [원본 JSON](raw/seoul-elevator-coordinates-20261028.json)552행이다. 조회일은2026-10-28이지만 자료 설명의 조사 기준은2020년이다. 출처: 서울특별시 서울열린데이터광장 OA-21212, 공공누리1유형.
- 역 안내도 출처: 서울교통공사·서울열린데이터광장 OA-11984, 공공누리1유형. 전체 ZIP은 약255MB이므로 저장소에 넣지 않았다. 직접 확인한17장 중 삼성·방배·아차산·청담4장만 [원형 JPEG](review-evidence/maps)로 보존하며 나머지13장은 ZIP 내부 경로·해시로 식별한다. 도면의 기존 첫차/막차 등 부수 정보는 현재 서비스 안내로 사용하지 않는다.
- 위 자료는 검수 근거이며 앱 카탈로그에 합치지 않았다. 이름 정규화·최근접 거리·설치 존재만으로 거점 좌표를 옮기거나 verified를 승인하지 않는다.

재현: JSON의 OA-11984 downloadUrl/downloadForm으로 공식 ZIP을 받은 뒤 `python scripts/audit-hub-access-20261028.py <ZIP 경로>`를 실행한다. Python 표준 라이브러리만 사용하며 ZIP·원문·표본 버전을 검사한 뒤 같은 보고서를 만든다. 새 자료나 다른 표본은 이 날짜의 검수를 덮어쓰지 말고 별도 날짜로 재검수한다.

[인천 운영역6개 대조 JSON](review-evidence/incheon-access-2026-10-28.json)은 위 자료에 대응하지 않았던 현재 표본6개의 공식 웹 텍스트를 검토한 별도 근거다. 출입구·층·방향 안내와 불일치 사항을 수동 요약하고 원문 링크·기관 역코드·현재 거점 fingerprint를 기록했다. 안내 이미지·현재 설비 가동·현장 검증은 포함하지 않으며 원문 페이지나 이미지는 복제하지 않았다. 두 검수의 합집합27역은 일부 근거가 있는 수이며 승인 수가 아니다. 대표점·보행 접근성 승인과 출시 거점은0개다.

## 격리된 동명 거점 대조

[격리 그룹 JSON](review-evidence/ambiguous-hubs-2026-10-28.json)은 제외된583개(철도239·버스344)를278개 동명 그룹으로 대조한 검수 목록이다. 동일 좌표3그룹은 동명 그룹에도 포함되어 중복 합산하지 않는다. 원본 해시·ID·지문·노선/ARS ID와 그룹 내 최대 직선거리를 기록한다. 양평53.6km·운정3.6km처럼 이름이 같아도 서로 떨어진 원본이 있으며, 가까운 점도 공통 만남 공간이라는 증거가 아니다. 그룹 수를 출시 거점 수로 사용하지 않는다.

재현: `node scripts/audit-hub-ambiguity-20261028.mjs`. 기존 정규화 함수·원본·품질보고서를 대조하고 날짜 고정 검수 JSON만 쓴다. 후보·승인·출시 데이터는 변경하지 않는다. 지점별 채택·명칭 구분·대표점 선정은 [후속 검수](../docs/HUB-REVIEW.md)의 근거를 확보한 뒤 진행한다.
