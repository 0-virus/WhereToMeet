# WhereToMeet 작업 전 브리핑

**기준일: 2026-10-14 · 판정: 핵심 기능 구현 및 로컬 검증, 출시 차단**

모든 후속 작업 전에 읽는 현황 문서다. 구현 사실, 검증 범위, 출시 차단 조건, 에이전트와 사용자의 다음 작업을 구분한다. 빠르게 확인하려면 **1 현황 요약 → 6 에이전트 작업 → 7 사용자 작업** 순서로 읽는다.

- 조사한 코드: `47ce57e0137973baeb9c07b63ef03077e1649096` (2026-10-05, 취소 후 정리 작업의 실행 수명 보호 및 통합 검증 기록).
- 조사 당시 작업 폴더는 브랜치에 연결되지 않은 커밋을 가리키는 상태였고 추적 파일 변경은 없었다. 이 상태는 조사 당시의 기록이므로 다음 작업에서 다시 확인한다.
- 기능과 정책의 기준은 [승인된 구현 계획](IMPLEMENTATION.md)이다. 원래 [실행 계획](20260923_실행계획.md)과 충돌하면 승인된 계획을 우선한다. 검색 기록과 즐겨찾기는 승인된 범위에 포함된다.
- 이 문서의 다음 작업 순서는 2026-10-14 브리핑의 제안이다. 새로운 범위 변경이나 공개 배포 승인을 의미하지 않는다.
- 과거 검증은 해당 날짜와 코드에 대한 증거다. 후속 변경이 있으면 영향을 받는 검사를 다시 실행하고 이 문서의 기준일·결과·차단 조건을 갱신한다.

### 검증 환경과 해석

- Node 24.21.0과 기존 설치 의존성·Chrome을 재사용했다. 별도 SDK·브라우저·패키지 설치는 하지 않았다.
- 초기 Vite 실패는 연결된 의존성 디렉터리의 캐시 쓰기 권한 문제였다. 캐시를 현재 작업 폴더 안에 쓰도록 의존성 연결 구조를 조정한 뒤 빌드가 통과했다.
- 초기 브라우저 실패는 Chrome 설치 경로를 찾는 환경변수 누락이었다. 실제 설치 경로에 맞춰 자식 프로세스 환경을 보완했다.
- 브라우저 재실행은 원래 테스트를 가져오는 임시 설정으로, 이번 검사에서 이미 시작한 로컬 테스트 서버를 재사용했다. 저장소의 정식 Playwright 설정은 변경하지 않았다.
- UI는 API 응답을 대체한다. 통합 검사는 실제 Worker 핸들러와 SQLite를 쓰지만 외부 장소·교통 응답은 테스트용이다. **113개 자동 테스트 통과는 실제 공급자 품질·원격 Cloudflare·실기기 검증을 대신하지 않는다.**
- Worker 배포 사전검사은 10월 5일 통과 기록이 있으나 이번에는 통과로 판정하지 않았다. 로컬 D1 마이그레이션 성공과 구분한다.
- 소스를 수정하거나 원격 배포하지 않았다. 로컬 빌드·검증 산출물만 만들었고, 검사에 사용한 4174·4181 포트의 서버는 종료 후 리스너가 없음을 확인했다.

환경과 테스트 범위 참고: [프로젝트 안내](../README.md), [기존 통합 검증](검증결과.md), [UI 설정](../tests/e2e/playwright.config.ts), [전체 흐름 설정](../tests/fullstack/playwright.config.ts). 임시 실행 파일과 산출물은 [추적 제외 설정](../.gitignore)에 따라 추적되지 않으며, 후속 작업의 영구 근거로 의존하지 않는다.

## 3 구현된 사용자 기능

### 출발지와 약속 입력

- 참가자 2~4명 추가·삭제, 검색 결과 선택으로 출발 좌표 확정.
- 선택한 장소 이름을 수정하면 이전 좌표 무효화.
- 키보드 자동완성 선택, 취소 가능한 검색 요청.
- 한국 시각 기준 현재 이후 7일 이내의 약속 입력.
- 서버에서 인원·중복 ID·유효 좌표·날짜를 재검사하고, Kakao 행정구역 응답으로 서울·경기·인천 여부 확인.
- 실제 Kakao 키가 없으면 설정 오류를 안내하며 가짜 검색 결과를 제공하지 않음.

출처: [출발지 입력](../src/PlaceInput.tsx), [앱 화면](../src/App.tsx), [클라이언트 시간 처리](../src/api.ts), [입력 검증](../server/validation.ts), [지역 검증](../server/kakao.ts), [UI 테스트](../tests/e2e/app.spec.ts).

### 추천과 상세

- 최대 4개 추천. 가장 큰 개인 부담 → 전체 부담 합 → 거점 ID 순으로 정렬.
- 부담은 이동시간과 조기 도착 대기시간의 합. 개인별 출발·도착·이동·대기·환승 표시.
- 과거 출발이 된 결과의 재검색 안내, 검색 취소, 중복 요청 방지.
- 이전 검색의 늦은 응답이 새 결과나 북마크 상태를 변경하지 않도록 보호.
- 정상적인 경로 없음과 공급자 오류를 구분.

예를 들어 20분·60분 부담의 장소보다 45분·45분 부담의 장소가 우선한다. 현재 출시 카탈로그는 비어 있어 정상 추천 요청도 `CATALOG_NOT_READY`로 차단된다.

- 클릭 시 지도 SDK 로딩, 로딩 실패 시 재시도와 외부 카카오맵 링크.
- 선택한 분류에 대해서만 주변 800m·최대 15개 조회. 식당·카페·문화/놀거리 지원.
- 공개 거점 또는 선택한 장소 링크 공유. 출발지와 약속 시각은 공유 URL에서 제외.
- 공유 취소, 복사 실패, 수동 복사 안내를 구분.

실제 지도 SDK·도메인 키, 실제 장소 결과, 모바일 외부 앱 전환·복귀는 검증이 남아 있다.

### 검색 기록과 즐겨찾기

- 익명 브라우저 쿠키로 소유자를 구분하고 정상·경로 없음 검색을 저장.
- 기록을 열 때 경로를 새로 계산하며, 과거 약속은 새 시각 입력 요구.
- 일반 기록은 마지막 성공 또는 경로 없음 검색 후 90일, 즐겨찾기 기록은 직접 삭제 전까지 보관.
- 만료된 기록의 마지막 즐겨찾기를 해제하면 기록 삭제.
- 즐겨찾기 우선 정렬, 재검색 시 기존 즐겨찾기 보존, 개별·전체 삭제.
- 기록 저장 실패 시 추천은 유지하면서 경고 표시.
- 다른 기기와 자동 동기화하지 않음. 쿠키 삭제·상실 후에는 기존 기록에 접근하지 못할 수 있음.

## 4 추천 엔진과 운영상의 한계

### 계산 흐름

1. 참가자별 출발 방향의 도달 가능 영역을 구한다.
2. 모두 도달할 수 있는 거점을 찾는다.
3. 30분에서 시작해 필요하면 60·120·240분까지 넓힌다. 현재부터 약속까지 남은 시간으로 상한을 제한한다.
4. 탐색 간격이 180초 이내가 될 때까지 범위를 좁힌다.
5. 남은 후보 모두를 도착시각 기준 경로 일괄 조회로 다시 조회한다.
6. 사람 누락·지각·과거 출발·잘못된 시간·허용하지 않은 교통수단을 제거하고 순위를 정한다.

폴리곤 구멍·경계를 보존하며 같은 좌표의 중복 조회를 줄인다. 응답 본문은 8MiB로 제한하고, 일시 오류는 남은 시간·호출 예산 안에서 한 번만 재시도한다.

현재 D1 ID는 모두 0인 로컬용 값이고 환경은 개발용이다. 사전 검증·운영 환경의 실제 계정·DB·도메인·비밀키·요청 빈도 제한·계약 호출 한도 설정이 필요하다. HTTPS 쿠키, API 캐시 방지, 로그 개인정보, 예약 실행 작업, 백업·복구와 롤백을 실제 환경에서 검증해야 한다.

검증용 100개 샘플을 만드는 것과 100개로 출시 범위를 줄이는 것은 다른 결정이다. 키 값은 채팅·Git에 올리지 않고 로컬 비밀 설정 또는 배포 환경의 비밀 설정으로 제공한다. 서버 키는 `.dev.vars`, 제한된 공개 Kakao JavaScript 키는 `.env.local`을 사용하며, 실제 명령줄 검증은 [경로 검증 문서](ROUTING-VALIDATION.md)의 환경 파일 방식에 따른다.
