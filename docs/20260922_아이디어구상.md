# 초기 서비스 구상

| 항목        | 내용                                                                         | 비고                                                 |
| ----------- | ---------------------------------------------------------------------------- | ---------------------------------------------------- |
| 서비스 지역 | 초기에는 수도권으로 한정                                                     | 추후 타 지역이나 지역 간 연계(시외버스 등) 고려      |
| 교통편      | 버스, 지하철 등 대중교통 한정                                                | 추후 자동차 등 확장                                  |
| 플랫폼      | Android 우선                                                                 | 웹을 MVP에 포함할지, 크로스플랫폼으로 할지 결정 필요 |
| 인원        | 2~4명                                                                        |                                                      |
| 추천 기준   | 최장 이동시간 최소화(주요 서비스 로직 참고), 동률 시 전체 이동시간 합 최소화 |                                                      |
| 사용 방식   | 회원가입 없이 이용 가능                                                      |                                                      |

## 주요 서비스 로직: 중간 지점 찾기

1. 지하철역을 포함한 주요 교통 거점 선정(1000~3000개)
2. 2~4개의 출발 지점을 입력받으면 isochrone api(ODSay, TravelTimes 등)를 활용해 모든 출발점의 등시간권에 속하는 교통거점이 존재하는 최소 시간과 해당 지점을 추적
   - 최대 시간을 지정(출발점 간 길찾기 시간의 최댓값으로 하면 좋지 않을까)하여 이분 탐색 활용(3-5분 오차에서 멈추면 적당하지 않을까)
3. 후보지가 선정되면 각 후보지별 실제 시간과 교통정보를 취합하여 종합 점수 순으로 추천 순위 설정(가중치 등 활용)

## 부가 서비스 및 확장 아이디어

### MVP 필수 포함

1. 후보지 근처 식당/카페/놀거리 등 안내
2. 선택 후보지 공유 기능(지도 앱으로 공유 또는 앱 링크 공유)

### 선택

1. 대중교통/자동차 모드 분리
2. 검색 기록 저장 기능 (api 호출 비용 절약용, 철저한 로그 관리 필요)
3. AI Agent 활용 (어디에?)
4. 실시간 교통정보 반영(교통체증, 대중교통 파업, 사고 등)
5. 후보지 점수에 상권, 대중교통 환승 등의 가중치 반영

## 기타

### 검증

- Isochrone API는 보통 실시간 교통정보를 반영하지 못함.
- 교통정보를 반영한 실제 길찾기 결과 소요시간과 비교할 수 있는 지표를 만들어 검증하는 절차가 필요.
