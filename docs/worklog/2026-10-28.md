## 로컬 프론트 테스트 가능 여부 확인

- [개발 안내](../../README.md), [Vite 설정](../../vite.config.ts), [UI 테스트 설정](../../tests/e2e/playwright.config.ts), [통합 테스트 설정](../../tests/fullstack/playwright.config.ts)을 확인했다. Node 24에서 `npm run dev`로 화면을 실행할 수 있고, 실제 API 연결은 로컬 DB 준비와 `npm run dev:worker`가 필요하다.
- 5173·8787·4174·4181의 루트 HTTP 요청은 모두 `ECONNREFUSED`였다. 확인한 포트에서 실행 중인 서버는 없으며 이번에는 서버를 시작하지 않았다. 포트 목록 조회는 권한 오류가 있어 HTTP 연결로 확인했다.
- UI 자동 테스트는 테스트 응답으로 추천 이후 화면을 검사할 수 있다. 실제 서버의 추천은 출시 카탈로그가 비어 있어 차단된다. 이전 19/19 통과는 10월 27일 기록이며 이번에는 테스트를 재실행하지 않았다.
- 제품 코드 변경 없음. 다음 에이전트 작업은 테스트 실행 요청 시 필요한 서버 구동·브라우저 확인, 다음 사용자 작업은 Node 24 터미널에서 개발 명령 실행 또는 테스트 실행 요청이다. 기존 출시 차단 조건은 유지한다.

## 실질적인 프로젝트 변경에만 자동 커밋 적용

- 사용자 요청에 따라 [작업 지침](../../AGENTS.md)과 [README](../../README.md)를 수정했다. 단순 조회·질문 답변·상태 재확인·실행 안내는 worklog 작성과 자동 커밋·푸시를 생략한다. 코드·설정·데이터·계획·지침의 실질적인 수정이나 새 검증 결과·차단 조건을 남기는 문서 변경에만 완료 절차를 적용한다.
- [종료 훅](../../scripts/finish-work-hook.mjs)의 안내도 동일하게 변경했다. Git 변경 감지 자체는 작업의 성격을 판별하지 못하므로, 에이전트가 적용 조건을 먼저 확인한다. 기존 사용자 변경·미푸시 커밋만으로 자동 커밋·푸시하지 않으며 명시적인 사용자 요청은 따른다. 훅 등록 정의와 감지 로직은 변경하지 않았다.
- 검증: `node --test tests/finish-work-hook.test.mjs` 5/5 통과, 변경 diff 검토 및 `git diff --check` 통과. 안내 문구·지침 수정이므로 앱 전체 테스트·실제 API·브라우저·실기기 검증은 재실행하지 않았다. Codex 실제 Stop 이벤트에서의 안내 반영은 미검증이다.
- 변경 파일: `AGENTS.md`, `README.md`, `scripts/finish-work-hook.mjs`, 이 worklog. 이번 요청 자체는 지침의 실질적인 수정이므로 한 번 커밋·푸시한다. 기존 확인 기록과 커밋은 소급 삭제하지 않는다.
- 현재 상태: 자동 커밋 적용 범위 수정 완료. 제품의 기존 경로 품질·거점 검수·운영/기기 출시 차단은 그대로다. 에이전트는 다음 단순 확인부터 기록·커밋을 생략한다. 사용자에게 추가 필수 작업은 없다.
