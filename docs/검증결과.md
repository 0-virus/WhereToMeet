# WhereToMeet 통합 검증 결과

검증일: 2026-10-05. 판정: **로컬 구현·자동화 검증 완료, 출시 차단(BLOCKED)**.

작업 0~5를 각각의 에이전트가 분리된 worktree에서 수행하고, 공통 타입·API·카탈로그·추천 엔진 계약을 공유하여 통합했다. 디자인은 `DESIGN-airbnb.md`를 적용했다. 공급자·기기·현장 검증을 포함한 사용자의 최종 완료 기준은 아직 충족하지 않았다.

## 실행 결과

Windows, Node 24.21.0, 설치된 Chrome에서 실행했다. 브라우저 테스트는 메모리 사용을 제한하기 위해 한 worker를 사용한다.

화면 테스트는 외부/API 응답을 대체한다. 전체 흐름 테스트는 서버와 SQL을 실제 실행하지만 Kakao 응답과 경로 결과를 테스트용으로 주입한다. 어느 결과도 실제 이동시간 품질, 원격 Cloudflare 동작 또는 실기기 검증의 증거로 사용하지 않았다.

실제 로컬 Wrangler 스모크 검사에서는 `/`, 공개 거점 SPA 경로, 잘못 인코딩된 SPA 경로가 HTML로 응답했다. `/api/history`는 200 JSON·`no-store`·보안 쿠키, 키 없는 장소 검색은 안전한 `CONFIG_NOT_READY` 503으로 응답했다. manifest와 서비스 워커의 콘텐츠 유형·갱신 헤더도 확인했다. 테스트 서버는 검증 후 종료했으며 원격 서비스는 배포하지 않았다.

검증 중 6개 브라우저 worker 실행은 자원 부족과 도구 재시작으로 중단되었다. 한 worker로 전체 19개를 재실행해 통과했다. 샌드박스 변경 후 테스트 서버 종료가 멈춘 실행은 현재 명령행을 확인한 테스트 프로세스만 정리하여 종료 코드 0을 확인했다. 앱 결함과 실행 환경 문제를 구분했다.

## 수정 및 재검증

- 후보 샘플에 출발역이 빠져 시나리오 생성이 막히던 문제: 출처가 있는 공공 출발 좌표를 목적지 샘플과 독립시켰다.
- 검색 중 현재 시각이 진행되면 출발 상한을 다시 계산하고, 과거 출발을 최종 추천에서 제거한다.
- 양쪽 모두 경로가 없는 사례는 정확도 성공률 분모에 넣지 않는다. 측정 스트림은 크기를 제한하면서 실제 공급자 오류·재시도를 유지한다.
- 취소한 quota 대기는 외부 요청을 시작하지 않는다. API 오류/시간 초과와 정상 경로 없음은 구분한다.
- 취소 중 D1 쓰기 완료 시 정확한 소유자·쓰기 revision만 보상한다. 기존 북마크나 이후 성공한 검색을 되돌리지 않는다. `waitUntil`이 후속 처리를 추적한다.
- 취소 정리가 진행 중일 때 중복 검색 잠금이 먼저 풀리던 35초 경계를 수정했다. 잠금은 기존 예약과 같은 90초까지 유지하며, 정리가 끝나면 즉시 해제한다. 36/60/89.999초 중복 거부와 90초 복구를 SQL 회귀 검사로 확인했다. 응답 후 후속 작업은 최대 30초이므로, 앱의 30초 요청 기한과 이 범위를 함께 보호한다. [Cloudflare 실행 수명](https://developers.cloudflare.com/workers/runtime-apis/context/)
- 만료 기록의 마지막 북마크 해제는 삭제 시점의 시각·북마크 상태를 SQL에서 확인한다. 사용 중 익명 쿠키는 같은 토큰으로 만료를 갱신한다.
- 이전 검색의 늦은 북마크 응답은 새 결과의 저장 상태·오류·진행 상태를 변경하지 않는다. 참가자 추가/삭제, 키보드 선택과 오류 초점도 브라우저에서 검사했다.

DB 장애나 Worker 강제 종료로 보상 처리가 끝나지 못하면 원자적 롤백을 보장할 수 없다. `HISTORY_ROLLBACK_FAILED`를 감시하고 운영 복구 절차를 검증해야 한다. 이 한계는 자동화 통과로 사라지지 않는다.

추천/측정 코어와 앱/서버를 별도 에이전트가 검토했다. 코어 5건과 앱 4건의 지적 및 후속 취소 중첩 조건을 수정 후 재검토했으며, 해당 수정 범위에서 잔여 차단 결함은 보고되지 않았다. 외부 출시 조건은 여전히 별도다.

`ROUTING_APPROVED=false`와 빈 출시 카탈로그를 유지했다. 가짜 이동시간·임의 도메인·서명 키·실험 결과로 미충족 조건을 덮지 않았다. 파일 경로나 존재 검사만 통과했다고 공급자 승인·서명 진위·실측 완료로 보지 않는다.

입력해야 할 항목은 질문으로 남겨 두었다. 비밀키는 대화나 Git에 올리지 않고 로컬 환경/비밀 관리에 설정한다. [시나리오별 현황](SCENARIOS.md), [운영 준비](운영준비.md), [배포 절차](DEPLOYMENT.md), [Android 준비](../android/README.md), [경로 검증 절차](ROUTING-VALIDATION.md)에 재현 방법과 후속 절차가 있다.
